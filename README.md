# UNO Q 코드 편집기 — 교사용 안내

크롬북의 크롬 브라우저에서 USB-C로 연결한 **Arduino UNO Q**의 코드를 열고, 고치고, 실행하는 웹앱입니다.
설치할 프로그램은 없고, `index.html` 파일 하나로 동작합니다.

## 어떻게 동작하나요?
UNO Q를 USB-C로 연결하면 보드 안의 리눅스(데비안)가 **ADB** 장치로 보입니다. 이 웹앱은 크롬의 **WebUSB** 기능으로 ADB에 접속해서 다음 일을 합니다.

- `/home/arduino/ArduinoApps` 안의 앱 목록 보여 주기
- 앱의 `sketch/sketch.ino`, `python/main.py`, `sketch/sketch.yaml` 열기·고치기·저장하기
- `arduino-app-cli app start`로 실행하기(스케치를 컴파일해서 MCU에 올림), `app stop`으로 정지하기
- `arduino-app-cli monitor`로 스케치의 `Monitor.print` 출력 보여 주기

> ⚠ Arduino Cloud 웹 에디터는 UNO Q에 Web Serial로 업로드하지 않습니다. UNO Q는 App Lab 방식(앱 = 스케치 + 파이썬)으로 동작하기 때문입니다.

## 1. 웹앱 올리기 (최초 1회)
WebUSB는 **https 주소**에서만 동작합니다. 둘 중 하나를 고르세요.

1. **GitHub Pages (권장)**: 저장소를 만들고 `index.html`을 올립니다. Settings → Pages에서 공개하면 `https://아이디.github.io/저장소이름/` 주소가 생깁니다. 이 주소를 구글 클래스룸에 올리세요.
2. **파일로 열기**: `index.html`을 학생 구글 드라이브나 크롬북 '내 파일'에 내려받아 크롬으로 엽니다(`file://`도 크롬에서 보안 주소로 취급됩니다).

## 2. 보드 준비 (보드당 최초 1회, 교사 PC)
- 윈도우 PC의 **Arduino App Lab**으로 각 보드를 처음 설정하고(이름·비밀번호·업데이트), 보드 이름을 `unoq-01`, `unoq-02` 식으로 정해 두면 편합니다.
- App Lab에서 예제 **Blink**를 한 번 실행해 보세요. 이렇게 하면 컴파일에 필요한 파일이 보드에 미리 받아져서 수업 중 첫 실행이 빨라집니다.

## 3. 학생 사용 순서
1. USB-C **데이터 케이블**로 크롬북과 UNO Q 연결 → 30초~1분 기다리기(보드 부팅)
2. 웹앱에서 **[보드 연결]** → 팝업에서 UNO Q 선택 → [연결]
3. 왼쪽 **[＋ 새 앱]** → 이름(예: `3jo-bangrye`) + 시작 코드 **"01차시 명제 — 반례 감지기"** 선택
4. 코드에서 조건(`x < 15`, `x < 30`)을 고치고 **[▶ 저장 후 실행]** (Ctrl+Enter)
5. 아래 **모니터** 탭에서 `x = 12 cm | p: 참 | q: 참` 같은 출력 확인

## 3-1. 차시별 실습 코드
**[＋ 새 앱]** 창에서 차시를 고르면 앱 이름(예: `l02-daeu`)이 자동으로 채워집니다. 같은 이름이 이미 있으면 `-2`, `-3`이 붙습니다.
학생이 고칠 부분은 코드 안에 **★ [학생 수정 영역]** 으로 표시했고, 맨 아래에 **[미션]** 주석이 있습니다.

| 차시 | 실습 코드 | 학생이 고치는 것 | 보는 것 |
| --- | --- | --- | --- |
| 00 | 연결 확인 — LED 깜빡이 | – | 보드 LED, 모니터 숫자 |
| 01 | 명제와 조건 — 반례 감지기 | 조건 p, q | p→q 반례 알림 |
| 02 | 역과 대우 — 세 명제 동시 검사기 | 조건 p, q | 명제·역·대우 반례 수 성적표 (명제 = 대우) |
| 03 | 충분·필요조건 — 진리집합 판정기 | p, q의 구간 | P⊂Q, Q⊂P 판정, 충분/필요/필요충분 결론 |
| 04 | 함수 — 정의역·공역·치역 매핑 | f(x) 식 | 파랑 LED 밝기 = f(x), 치역 범위, 공역 밖 경고 |
| 05 | 합성함수와 역함수 — 파이프라인 | f, g, f⁻¹ 식 | (g∘f)(x)와 (f∘g)(x) 비교, 역추적 성공 여부 |
| 06 | 원의 방정식 — 지오펜스 | 중심 (a, b), 반지름 r | 조이스틱 점의 원 내부/위/외부 판정 |

### 📐 수학 화면 — 실행하면 무엇이 바뀌는지 눈으로 보기
차시 코드로 만든 앱을 열면 편집기 오른쪽에 **📐 수학 화면**이 열립니다. 보드가 계산한 결과를 그림으로 보여 줍니다.

| 차시 | 수학 화면에 그려지는 것 |
| --- | --- |
| 01~03 | 수직선 위의 진리집합 P(초록)·Q(파랑), 반례 구간(빨강), 손의 거리 x 위치(▼), 센서로 잰 x 기록 |
| 04 | y=f(x) 그래프, 공역 띠, 치역 막대, 공역 밖 점(빨강), 지금 x의 LED 밝기 |
| 05 | x → f → g 파이프라인, (g∘f)(x)와 (f∘g)(x) 그래프 비교, f⁻¹(f(x))와 y=x 비교 |
| 06 | 좌표평면 위의 원, 조이스틱 점, 원 위의 격자점(○ → 찾으면 ●) |

- 보드는 조건 p(x), q(x)를 전체집합 U = {0, …, 60}의 **모든 원소에 하나씩 넣어 계산한 결과**를 보냅니다. 그래서 학생이 조건을 어떻게 고쳐도 화면의 진리집합은 실제 코드와 정확히 같습니다.
- 코드를 고치고 다시 실행하면 맨 위에 **🔁 이번 실행에서 바뀐 것**이 나옵니다(예: `P : {0 ≤ x ≤ 14} → {0 ≤ x ≤ 39}`, `반례 구간 : 없음 → 30~39`). 바뀌기 전 모습은 점선으로 남습니다. 아무것도 안 바꾸고 실행하면 "지난 실행과 같아요"라고 알려 줍니다.
- 컴파일하는 동안에는 **🤔 예상해 보기** 질문이 나옵니다. 결과가 나오기 전에 학생이 예측하게 하세요.
- 그림을 누르거나 끌면 x(또는 점)를 직접 고를 수 있습니다. 센서가 없거나 고장 나도 수업을 이어 갈 수 있습니다.
- 아래 **🧭 무엇을 볼까요?**에 차시별로 '바꿀 것 → 볼 것'이 체크리스트로 있습니다.
- 수학 화면은 스케치가 보내는 `@`로 시작하는 줄(맨 아래 "수학 화면으로 보내기" 부분)을 읽어서 그립니다. 이 줄은 모니터 탭에는 보이지 않습니다. 예전에 만든 앱에는 이 부분이 없으므로 **[＋ 새 앱]으로 다시 만들어** 주세요.

**공통 키트 배선** (한 번 꽂아 두면 모든 차시에 그대로 사용)
- 초음파 HC-SR04: Trig `D2`, Echo `D3`
- 초록 LED `D8`, 파랑 LED `D9` (04차시는 D9 밝기 조절)
- 조이스틱 모듈: VRx `A0`, VRy `A1` (06차시만)

같은 코드가 `아두이노수학/source코드/` 폴더에 `.ino` 파일로도 저장되어 있습니다.

## 4. 꼭 알아 둘 차이점 (기존 수업 자료 수정 필요)
| 기존 UNO R3 방식 | UNO Q 방식 |
| --- | --- |
| `Serial.begin(9600)` | `#include <Arduino_RouterBridge.h>` + `Monitor.begin()` |
| `Serial.print(...)` | `Monitor.print(...)` |
| Arduino Cloud에서 업로드 | 이 웹앱(또는 App Lab)에서 **실행** |

- 코드에 `Serial.print`가 있으면 편집기 위에 노란 안내가 뜨고, **[Serial → Monitor 자동 바꾸기]** 버튼으로 한 번에 바꿀 수 있습니다.
- UNO Q의 핀은 **3.3V** 기준입니다. HC-SR04를 5V로 쓰면 Echo 신호도 5V가 됩니다. 보드 문서에서 D3 핀이 5V를 견디는지 확인하고, 아니라면 **HC-SR04P(3.3V 지원)** 모델이나 저항 분압(1kΩ/2kΩ)을 쓰세요.

## 5. 문제 해결
| 증상 | 해결 |
| --- | --- |
| [보드 연결] 팝업에 아무것도 없음 | 보드 부팅이 끝날 때까지 1분 기다리기, 데이터 케이블인지 확인 |
| "보드를 다른 곳에서 쓰고 있어요" | 편집기 탭이 2개 열려 있는지 확인, 하나만 남기고 USB 다시 꽂기 |
| 학교 관리 크롬북에서 USB 팝업이 안 뜸 | 구글 관리 콘솔에서 WebUSB가 막혀 있을 수 있음 → 정보부장/관리자에게 웹앱 주소의 WebUSB 허용 요청(`WebUsbAskForUrls` 정책) |
| `Arduino_RouterBridge.h: No such file` | `sketch.yaml` 탭의 `libraries:` 목록에 `Arduino_RouterBridge`가 있는지 확인하거나, App Lab에서 그 앱에 라이브러리 추가 |
| `Library install failed ... dial tcp ... lookup downloads.arduino.cc` | 보드가 인터넷에 연결되지 않아 라이브러리(예: `ArxTypeTraits`)를 못 받은 것 → 아래 **보드 Wi-Fi 연결**을 한 번 해 주세요 |
| `undefined reference to 'pulseIn'` | 보드 코어(0.52.x)에 `pulseIn`이 없음 → 웹앱이 같은 동작을 하는 코드를 스케치 끝에 붙일지 물어봅니다. [확인]을 누르면 자동으로 고치고 다시 실행합니다. (차시 코드는 처음부터 `pulseIn`을 쓰지 않습니다) |
| 모니터에 아무것도 안 나옴 | `Monitor.print`를 썼는지 확인하고, [모니터 연결]을 다시 누르기 |
| 그 밖의 명령이 필요할 때 | **터미널(교사용)** 탭에서 보드 명령을 직접 실행 (예: `arduino-app-cli app list`) |

### 인터넷 없는 보드에서 실행하기
`Monitor`를 쓰는 코드는 `Arduino_RouterBridge` → `MsgPack` → `DebugLog` → `ArxTypeTraits` 라이브러리가 필요합니다. 보드에 기본으로 없는 **`ArxTypeTraits`(MIT 라이선스)는 웹앱에 들어 있습니다**. 그래서 **[보드 연결]**을 누를 때 보드에 없으면 자동으로 넣어 줍니다. 실행 기록에 "라이브러리 ArxTypeTraits … 을(를) 보드에 넣었어요"가 나오면 설치된 것입니다.

그래도 `Library install failed`가 뜨면 웹앱에 없는 다른 라이브러리가 필요한 경우입니다. [기록 복사]로 보내 주시거나 아래처럼 보드를 Wi-Fi에 한 번 연결하세요.

### 보드 Wi-Fi 연결 (필요할 때만)
한 번 받은 라이브러리는 보드에 저장되므로, 그다음부터는 인터넷이 없어도 됩니다.

- **방법 1 (App Lab):** 윈도우 PC의 App Lab에서 보드를 연결하고 네트워크 설정에서 Wi-Fi를 연결합니다.
- **방법 2 (이 웹앱의 터미널 탭):**
  ```
  nmcli device wifi list
  nmcli device wifi connect "와이파이이름" password "비밀번호"
  ```
  권한 오류가 나면 앞에 `sudo `를 붙이세요(보드 비밀번호 필요). 학교 Wi-Fi가 웹 로그인(인증 페이지) 방식이면 보드가 연결할 수 없으니, 교무실 Wi-Fi나 휴대폰 핫스팟을 쓰세요.
- 연결한 뒤 아무 차시 코드나 한 번 **[▶ 저장 후 실행]** 하면 라이브러리가 저장됩니다.
- 확인: 터미널 탭에서 `ls ~/.arduino15/internal` 을 실행해 `ArxTypeTraits_…` 폴더가 있으면 준비 완료입니다.

## 6. 고쳐서 다시 만들려면
`source/` 폴더에 원본이 있습니다. Node.js가 있는 PC에서 다음을 실행하면 `index.html`이 다시 만들어집니다.
```
cd source
npm install
node build.mjs ../index.html
```
